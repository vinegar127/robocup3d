# 3D 步态可视化工具（walkviz）

> **零依赖、双击即用。** 用浏览器打开 `index.html` 就行，不用装任何东西。

---

## 这是什么

一个单文件的 3D 人形机器人走路可视化工具，用来**建立「行走引擎」的直觉**。

它手写了一个极简 3D 渲染器（透视投影 + 画家算法），
**没有用 Three.js 或任何库** —— 这样你可以打开源码看到
「3D 其实就是把 3D 点投影到 2D 屏幕」，而不是把它当成魔法。

---

## 怎么用

**直接双击 `index.html`**，用 Chrome / Edge 打开。

（如果浏览器阻止本地文件，就用 `python -m http.server` 起一个本地服务，
然后访问 `http://localhost:8000/tools/walkviz/`）

| 操作 | 效果 |
|------|------|
| 鼠标左键拖动 | 旋转视角 |
| 滚轮 | 缩放 |
| 空格 | 暂停 / 继续 |
| 右侧滑块 | 实时调整步态参数 |

## 六个参数在调什么

调参是行走引擎的核心工作。**请务必一个一个试，观察变化。**

| 参数 | 含义 | 调大会怎样 | 调小会怎样 |
|------|------|-----------|-----------|
| **步幅** `step_length` | 脚往前迈多远 | 走得快，但容易劈叉摔倒 | 走得稳但慢 |
| **抬脚高度** `step_height` | 脚离地多高 | 不容易绊倒，但浪费能量、周期变长 | 调到 0 会拖地绊倒 |
| **周期** `cycle_time` | 走一步花多久 | 慢而稳 | 快，但重心来不及转移，容易摔 |
| **躯干高度** `body_height` | 身体蹲多低 | 站得高，视野好，但不稳 | 越低越稳，但膝盖负担大 |
| **左右摆胯** `sway` | 重心左右移动幅度 | 重心转移充分，更稳 | **调到 0 会直接摔倒** |
| **前倾** `lean` | 身体前倾角度 | 像起跑，适合加速 | 后仰会向后倒 |

### ★ 最重要的一个实验

**把「左右摆胯」滑块拖到 0，看右侧的稳定性提示。**

你会看到它变成红色警告。**这就是「重心必须落在支撑面内」这个
机器人学第一原理的直观体现。**

人走路时如果重心不左右移动，就会向一侧倾倒 ——
所以人走路本来就会左右晃。这不是「走得不好」，
而是**物理上的必然要求**。

## 预设动作

点这四个按钮，对比一下：

| 预设 | 参数特点 | 观察重点 |
|------|---------|---------|
| **正常行走** | 平衡参数 | 基准 |
| **冲刺** | 大步幅、短周期、大前倾 | 速度快，稳定性提示变成什么颜色？ |
| **龟速稳走** | 小步幅、长周期 | 很稳，但速度损失多少？ |
| **坏掉的步态** | 极端参数 | 稳定性提示全红 —— 看清楚是哪些参数导致的 |

## 和 Python 代码的关系

`index.html` 里的 JavaScript 逻辑，和 `walk.py` 里的 Python **完全一致**：

| Python (`walk.py`) | JavaScript (`index.html`) |
|-------------------|--------------------------|
| `LegKinematics.forward()` | `legForward()` |
| `LegKinematics.inverse()` | `legInverse()` |
| `GaitGenerator.step()` | `makeJoints()` |
| `GaitParams` | `P` 对象 |

**建议的学习顺序**：

```
1. 先在浏览器里玩（建立直觉）
        ↓
2. 再读 walk.py（看数学实现）
        ↓
3. 跑 python walk.py（看终端输出）
   └─ 它每 0.5 秒打印一次关节角、支撑脚数量、已走距离
```

## 直接跑 Python 版

```bash
cd tools/walkviz
python walk.py
```

输出示例：

```
  t(s)      左脚x       左膝       右膝    支撑脚    已走(m)
--------------------------------------------------------
  0.00     0.019    -47.1    -47.1       2     0.006
  0.50    -0.067    -43.8    -65.2       1     0.147
  1.00    -0.067    -43.8    -65.2       1     0.289
  1.50     0.019    -47.1    -47.1       2     0.431
```

**怎么看这些数字？**

| 列 | 含义 | 你应该注意什么 |
|----|------|--------------|
| `左脚x` | 左脚相对躯干的前后位置 | 应该在周期性前后摆动 |
| `左膝`/`右膝` | 膝关节角度 | 两腿角度**相差半个周期**（这就是走路） |
| `支撑脚` | 有几只脚接近地面 | ★ 应该在 1 和 2 之间循环：<br>1 = 单脚支撑（摆动相）<br>2 = 双脚支撑（换步瞬间） |
| `已走(m)` | 累计前进距离 | 应该线性增长 |

> ★ **如果「支撑脚」一直是 0，说明你的机器人两只脚都在空中 —— 它在飞，不是走。**
> 如果一直是 2，说明它没在迈步，只是在原地蹭。
> **这是检验步态是否正确的第一指标。**

## 已知简化

这个工具**故意**做了大量简化，以便你第一次就能看懂。
它不是物理仿真器：

| 简化 | 真实情况 |
|------|---------|
| 每条腿只有 3 个自由度 | 真实人形每腿 6 个自由度 |
| 没有动力学（不算力矩、惯性） | MuJoCo 会算完整的关节动力学 |
| 没有碰撞检测 | 脚会穿地、两腿会互穿 |
| 不考虑 ZMP / 稳定判据 | 真实行走引擎核心就是算这个 |
| 前进距离是理想估算 | 真实机器人会打滑 |

**所以**：不要试图用这个工具「调出能上场比赛的步态」。
它的用途是**建立直觉**，然后你才能看懂真实的行走引擎在干什么。

真正的物理验证要靠 `rcssservermj`（MuJoCo）。
