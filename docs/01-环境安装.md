## 1. 先装什么、后装什么

**依赖顺序不能乱。** 后一步依赖前一步，装错了会连环报错。

```
    ① Python 3.12            ← 一切的基础
         ↓
    ② Git                    ← 代码版本管理（不依赖 Python）
         ↓
    ③ VS Code + 插件          ← 写代码的地方（不依赖前两者）
         ↓
    ④ GitHub 账号 + 连接       ← 需要 Git
         ↓
    ⑤ 克隆仓库、跑 demo        ← 需要 ①②④
         ↓
    ⑥ （可选）WSL2            ← 需要 ① 的教训：先知道原生怎么玩
         ↓
    ⑦ （后期）MuJoCo 仿真器    ← 需要 ⑤ 跑通之后
```

> 💡 **为什么 Python 排第一？**
> 因为 `git` 和 `code` 这两个命令你能不能敲，取决于 PATH 配好没有；
> 而 Python 安装器是三个里**唯一会问你要不要自动配 PATH** 的。
> 先把它装好，你就能立刻验证「命令行到底是什么」这件事。

## 2. 第一步：Python

### 2.1 下载安装

1. 打开 <https://www.python.org/downloads/windows/>
2. 选择 **Windows installer (64-bit)**。

   **该选哪个版本？** 这是新手第一个会纠结的问题：

   | 版本 | 建议 | 理由 |
   |------|------|------|
   | **3.12.x** | ✅ **最保险，推荐** | 生态兼容性最好的稳定版本，几乎不存在「没有预编译包」的问题 |
   | **3.13.x** | ✅ 可以 | 主流库基本都支持了 |
   | 3.14.x 及更新 | ⚠️ 谨慎 | 部分机器人/AI 库的预编译包（wheel）可能还没跟上，你会被迫从源码编译，然后卡在 `Microsoft Visual C++ 14.0 or greater is required` |

   > 💡 **一句话原则**：机器人 / 科学计算生态永远比最新 Python 慢半步。
   > **不要盲目装最新版。** 如果后面装 MuJoCo、PyTorch 时报
   > 「找不到匹配的版本」或「需要 C++ 编译器」，八成就是 Python 太新了 ——
   > 换回 3.12，问题立刻消失。

   > 📌 版本号会变。**请以网页最上方显示的当前版本为准**，
   > 本指南不硬编码具体小版本号（硬编码的教程半年就过期了）。

3. 运行安装器，**在第一个界面底部务必勾选**：

   ```
   ☑ Add python.exe to PATH        ← ★★★ 最关键的一步，默认是【不勾】的！
   ☑ Install launcher for all users
   ```

   > ⚠️ 忘了勾会怎样？以后每次敲 `python` 都会提示
   > `'python' 不是内部或外部命令`。补救方法见 [第 9 章 E01](#e01)。
   >
   > 📌 新版本安装器可能把这个勾选项挪到了最后的完成页面，
   > 或者改叫 *Add Python to environment variables*。
   > **装完一定要用下面的命令验证**，不要凭印象。

4. 点击 **Install Now**，等待完成。

### 2.2 验证 ✅

**关掉所有已打开的终端**（PATH 是启动时读取的，旧窗口不会更新），
然后按 `Win + R`，输入 `powershell`，回车，敲：

```powershell
python --version
python -m pip --version
where.exe python
```

期望输出类似：

```
Python 3.12.8
pip 24.3.1 from C:\Users\你的用户名\AppData\Local\Programs\Python\Python312\Lib\site-packages\pip (python 3.12)
C:\Users\你的用户名\AppData\Local\Programs\Python\Python312\python.exe
```

**看到版本号 + 路径 = ✅ 通过。**

> ★ **注意我用的是 `python -m pip` 而不是直接敲 `pip`。**
> 请从现在开始养成这个习惯 —— 原因见 [E03](#e03)，
> 这是「明明装了却 ImportError」的头号元凶。
>
> 💡 如果 `python` 没反应，试 `py --version`。
> `py` 是 Python 启动器，**即使 PATH 没配好它通常也能用**，
> 是一个很好的救命通道。用 `py` 创建虚拟环境：
> `py -3.12 -m venv .venv`

### 2.3 额外建议：装上 `uv`（可选但强烈推荐）

`uv` 是新一代 Python 包管理器，安装和解析依赖比 pip 快 10~100 倍，
而且它**能自己管理 Python 版本**（`uv python install`），
以后再遇到「版本不对」的问题会轻松很多。
后面你装 MuJoCo、PyTorch 的时候会感谢它。

```powershell
# 官方一键安装脚本
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# 或者用 winget
winget install --id=astral-sh.uv -e
```

验证：

```powershell
uv --version
```

用法对照表（会 pip 就会 uv）：

| 你想干什么 | pip 写法 | uv 写法 |
|-----------|---------|--------|
| 创建虚拟环境 | `python -m venv .venv` | `uv venv` |
| 装依赖 | `pip install -r requirements.txt` | `uv pip install -r requirements.txt` |
| 跑脚本 | `python agent.py` | `uv run agent.py` |

> 如果下载超时（国内网络），这一节可以直接跳过，用 pip 也能完成所有事情。
> 也别忘了配 [pip 国内源](#10-pip-换国内源强烈建议)。

## 3. 第二步：Git

### 3.1 Git 和 GitHub 的区别（先搞清楚，不然会一直晕）

| | Git | GitHub |
|---|-----|--------|
| 是什么 | 一个**装在你电脑上的软件** | 一个**网站** |
| 干什么 | 记录代码的每一次修改，方便回退和协作 | 把你的 Git 仓库放到云上，方便共享 |
| 能不能离线用 | ✅ 能，完全离线也能用 | ❌ 不能 |
| 类比 | Word 的「修订历史」功能 | 把文档传到网盘共享 |

**一句话**：Git 是工具，GitHub 是存放的地方。没有 GitHub，Git 照样能跑。

### 3.2 下载安装

1. 打开 <https://git-scm.com/download/win>
2. 下载 **64-bit Git for Windows Setup**
3. 安装过程中的选项，对新手建议：

| 界面 | 选择 | 理由 |
|------|------|------|
| Select Components | 全默认 | — |
| Default editor | **Use Visual Studio Code** | 别选 Vim！新手会卡在里面出不来 |
| Initial branch name | **main** | 和 GitHub 默认一致 |
| PATH environment | **Git from the command line and also from 3rd-party software** | 默认就是，别改 |
| HTTPS transport | **Use the native Windows Secure Channel library** | 国内网络更稳 |
| Line endings | **Checkout Windows-style, commit Unix-style**（默认） | 见 [3.4](#34-三个必做的全局配置) |
| Terminal emulator | **Use MinTTY**（默认） | — |

### 3.3 验证 ✅

**关闭并重新打开 PowerShell**，敲：

```powershell
git --version
```

期望输出 `git version 2.4x.x.windows.1`。**✅ 通过。**

### 3.4 三个必做的全局配置

Git 装完第一件事就是告诉它「你是谁」。**只做一次，终身有效。**

```powershell
# ① 身份（会出现在你每一次提交记录里，请用真名或队内昵称）
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"

# ② 中文文件名不乱码（★ Windows 用户必做，否则中文文件名会显示成 \344\270\255）
git config --global core.quotepath false

# ③ 换行符：Windows 用 CRLF，Linux 用 LF。
#    这个设置让你「取出来是 Windows 格式，提交上去是 Linux 格式」，
#    避免和 Linux 队友协作时每一行都被标记成「已修改」。
git config --global core.autocrlf true

# ④ 中文提交信息正常显示（可选）
git config --global i18n.commitEncoding utf-8
git config --global i18n.logOutputEncoding utf-8
```

验证：

```powershell
git config --global --list
```

**✅ 看到 4 条配置 = 通过。**

2. 下载 **Windows User Installer (x64)**
3. 安装时**建议勾选**：

### 4.3 VS Code 关键设置（新手最常踩的两个坑）

按 `Ctrl+,` 打开设置，搜索并设置：

| 设置项 | 值 | 为什么 |
|--------|-----|--------|
| `files.encoding` | `utf8` | ★ 中文乱码的头号原因 |
| `files.autoGuessEncoding` | `true` | 打开别人文件时自动识别 |
| `files.eol` | `\n` | 和 Linux 队友保持一致 |
| `terminal.integrated.defaultProfile.windows` | `PowerShell` | — |
| `editor.formatOnSave` | `true` | 保存自动格式化 |
| `python.terminal.activateEnvironment` | `true` | 打开终端自动激活虚拟环境 |

### 4.4 把 VS Code 的 Python 解释器指向虚拟环境

**这一步 90% 的新手会漏，然后遇到 `ModuleNotFoundError`。**

1. 先创建虚拟环境（在项目根目录的终端里）：

   ```powershell
   python -m venv .venv
   ```

2. 激活它：

   ```powershell
   # PowerShell
   .\.venv\Scripts\Activate.ps1

   # 如果报「因为在此系统上禁止运行脚本」，先执行下面这行，然后重试
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```

   激活成功后，命令行前面会出现 `(.venv)` 字样。**这个括号就是你的安全带** ——
   看到它，说明你装的包进的是这个项目的环境，而不是全局。

3. 在 VS Code 里按 `Ctrl+Shift+P`，输入 `Python: Select Interpreter`，
   选择带 `.venv` 的那个。

**验证 ✅**：

```powershell
python -c "import sys; print(sys.executable)"
```

输出路径里应该含有 `.venv`。

## 5. 第四步：GitHub 账号与首次连接

### 5.1 注册

打开 <https://github.com/signup>，用邮箱注册。

**给队伍的建议**：
- 用户名用拼音或英文，别用中文（有些工具不支持）
- 队伍建议建一个 **Organization**（组织），把仓库放在组织下，
  而不是某个人的个人账号下 —— 否则这个人毕业了仓库会很麻烦

### 5.2 配置 SSH 密钥（推荐，一次配好终身免密）

> **为什么不用密码？** GitHub 在 2021 年就**彻底移除了密码认证**。
> 你现在 `git push` 时输密码会直接报错。必须用 SSH 密钥或 Token。

```powershell
# ① 生成密钥（一路回车即可，密码可以留空）
ssh-keygen -t ed25519 -C "你的邮箱@example.com"

# ② 查看公钥内容
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
```

复制输出的**全部内容**（以 `ssh-ed25519` 开头的一整行），然后：

1. 打开 <https://github.com/settings/keys>
2. 点 **New SSH key**
3. Title 随便填（如「我的笔记本」），Key type 保持 **Authentication Key**
4. 粘贴公钥，点 **Add SSH key**

**验证 ✅**：

```powershell
ssh -T git@github.com
```

第一次会问 `Are you sure you want to continue connecting?`，输入 `yes` 回车。

期望看到：

```
Hi 你的用户名! You've successfully authenticated, but GitHub does not provide shell access.
```

**看到 `Hi 你的用户名!` = ✅ 通过。**

> 如果卡住不动或超时 → 见 [第 9 章 E20](#e20)。

### 5.3 国内网络问题的应对

GitHub 在国内经常连不上或极慢。按**推荐顺序**尝试：

**方案 A：改 hosts（最简单，缺点是 IP 会失效）**

IP 会变动，所以不要抄网上的旧教程。自己查当前 IP：

```powershell
# 查 GitHub 各域名的当前 IP
Resolve-DnsName github.com -Type A | Select-Object Name, IPAddress
nslookup github.com 8.8.8.8
```

用管理员权限编辑 `C:\Windows\System32\drivers\etc\hosts`，添加：

```
<查到的IP>  github.com
<查到的IP>  api.github.com
<查到的IP>  raw.githubusercontent.com
```

然后刷新 DNS：

```powershell
ipconfig /flushdns
```

**方案 B：用代理 / 加速工具**

如果你已经有科学上网工具，让 Git 走代理：

```powershell
# 假设你的代理是 127.0.0.1:7890（按你实际端口改）
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890

# 取消代理（换网络环境时需要取消，否则反而连不上）
git config --global --unset http.proxy
git config --global --unset https.proxy
```

**方案 C：只对 GitHub 走代理**

```powershell
git config --global http.https://github.com.proxy http://127.0.0.1:7890
```

**方案 D：用镜像站下载（只用于 clone 公开仓库）**

> ⚠️ **重要提醒**：GitHub 加速镜像站**死得非常快**（政策、成本原因）。
> 网上流传的 `hub.fastgit.org`、`gitclone.com`、`ghproxy.com` 等**大多已经失效**。
> 所以本指南**不硬编码具体镜像域名** —— 请自行搜索「GitHub 加速 2026 可用」，
> 或者直接问你的学长学姐在用哪个。**不要盲目相信任何一篇超过半年的教程。**

用法一般是把 URL 拼成：

```
https://<当前可用的镜像域名>/https://github.com/owner/repo.git
```

**方案 E：Gitee（码云）中转**

如果实在连不上 GitHub，可以让一个能连上的同学把仓库**导入 Gitee**：

1. 打开 <https://gitee.com/projects/import/url>
2. 填入 GitHub 仓库地址
3. 之后全队从 Gitee 克隆

**代价**：Gitee 和 GitHub 不会自动同步，需要定期手动同步。

## 7. 第六步：Windows 终端与 PowerShell 基础

零基础同学请把这张表贴在显示器上：

| 你想干什么 | PowerShell 命令 | 类比 |
|-----------|----------------|------|
| 我现在在哪个目录 | `pwd` | 「我在哪」 |
| 看目录里有什么 | `ls` 或 `dir` | 「打开文件夹看看」 |
| 进入子目录 | `cd 文件夹名` | 双击文件夹 |
| 回上一层 | `cd ..` | 点「返回」 |
| 回到用户主目录 | `cd ~` | 回到桌面 |
| 清屏 | `cls` | 擦黑板 |
| 新建文件夹 | `mkdir 名字` | 右键新建 |
| 删除文件 | `rm 文件名` | 删到回收站（**不进回收站！慎用**） |
| 复制文件 | `cp a.txt b.txt` | 复制 |
| 移动/重命名 | `mv a.txt b.txt` | 剪切/重命名 |
| 查看文件内容 | `cat 文件名` | 记事本打开 |
| 看命令帮助 | `Get-Help 命令名` | 说明书 |

**三个新手必须知道的事**：

1. **Tab 键自动补全**。敲 `cd rob` 然后按 `Tab`，会自动补成 `robocup3d-prep`。
   少打很多字，也避免拼错。

2. **`↑` 方向键调出上一条命令**。不用重新敲。

3. **路径里不要有中文和空格**。
   `D:\我的项目\机器人 仿真\` 这种路径会让 Python、Git、CMake 各种报错。
   用 `D:\projects\robocup3d\` 这样最安全。

## 8. 第七步：WSL2（可选，但迟早要用）

### 8.1 要不要装？

| 场景 | 建议 |
|------|------|
| 只跑本仓库的 demo | ❌ 不需要，原生 Windows 完全够 |
| 读/编译 C++ 代码库（ApolloCodebase） | ⚠️ 建议装。Linux 下编译 C++ 顺畅得多 |
| 跑 MuJoCo 训练（需要显卡） | ✅ 建议装，且 WSL2 支持 GPU 直通 |
| 只是好奇 | 先跳过，等真的需要再装 |

### 8.2 安装（管理员 PowerShell）

```powershell
wsl --install
```

然后**重启电脑**。重启后会自动让你设置 Linux 用户名和密码。

```powershell
# 验证
wsl --list --verbose
```

应该看到 `Ubuntu` 且 `VERSION` 是 `2`。

```powershell
# 更新一下
wsl --update
```

### 8.3 WSL2 的坑（提前知道能省几小时）

| 坑 | 说明 |
|----|------|
| **文件性能** | 代码放在 `/mnt/d/...`（Windows 盘）会**慢 10 倍**。请把代码放在 WSL 自己的文件系统里，如 `~/projects/`。跨盘访问只用来传文件。 |
| **换行符** | WSL 里是 LF，Windows 是 CRLF。已经用 `core.autocrlf true` 解决（见 [3.4](#34-三个必做的全局配置)）。 |
| **权限** | WSL 里 `chmod +x` 对 `/mnt/` 下的文件经常不生效。所以脚本要放 WSL 文件系统。 |
| **图形界面** | 新版 WSL2 支持 GUI（WSLg），Linux 的窗口程序能直接弹出来。跑 RoboViz 需要它。 |
| **显卡** | WSL2 里**不要**自己装 NVIDIA 驱动，会自动继承 Windows 的。装了就坏。 |

### 8.4 在 WSL 里开发

装 VS Code 的 **WSL** 插件后，在 WSL 终端里输入：

```bash
code .
```

VS Code 会以「远程模式」打开 WSL 里的项目。这是最舒服的开发方式：
**编辑器在 Windows，代码和运行环境在 Linux。**

## 9. 常见报错速查（28 条）

> 遇到报错，先按 `Ctrl+F` 搜报错里的关键词。
>
> **使用建议**：不要从头读到尾 —— 那是浪费时间。**报错了再来查，只查你遇到的那一条。**

### E01
```
'python' 不是内部或外部命令，也不是可运行的程序
'python' is not recognized as an internal or external command
```
**原因**：安装 Python 时没勾「Add python.exe to PATH」。
**解决**：重装 Python 并勾上；或手动添加。
手动方法：`Win+R` → `sysdm.cpl` → 高级 → 环境变量 →
在「用户变量」的 `Path` 里添加 Python 安装目录和它的 `Scripts` 子目录，例如：
```
C:\Users\你的用户名\AppData\Local\Programs\Python\Python312\
C:\Users\你的用户名\AppData\Local\Programs\Python\Python312\Scripts\
```
**改完必须关掉终端重开。**

---

### E02
```
.\.venv\Scripts\Activate.ps1 : 无法加载文件 ...\Activate.ps1，因为在此系统上禁止运行脚本
```
**原因**：PowerShell 默认执行策略禁止运行脚本。
**解决**：
```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
# 提示时输入 Y 回车
```
（用 `-Scope CurrentUser` 只影响你自己，不需要管理员权限。）

---

### E03
```
ModuleNotFoundError: No module named 'numpy'
```
**原因**：① 没装；② **装了但装到了别的 Python 环境**（最常见）。
**解决**：
```powershell
# 先确认当前用的是哪个 python
python -c "import sys; print(sys.executable)"

# 再确认 pip 装到了哪里 —— 两个路径必须是同一个环境！
python -m pip --version

# 确认虚拟环境已激活（命令行前面应该有 (.venv)）
.\.venv\Scripts\Activate.ps1

# 再装
python -m pip install numpy
```
> ★ **记住这个万能写法：`python -m pip install xxx`**
> 它保证装到「你现在正在用的这个 Python」里，而不是别的环境。
> 直接敲 `pip` 有时会指向另一个 Python（尤其是你同时装了微软商店版和官网版时）。
>
> **VS Code 用户特别注意**：在 VS Code 的终端里跑
> `Ctrl+Shift+P` → `Python: Select Interpreter`，选带 `.venv` 的那个，
> 否则编辑器里报错、终端里不报错，你会疯掉。

---

### E04
```
Microsoft Visual C++ 14.0 or greater is required.
Get it with "Microsoft C++ Build Tools"
```
**原因**：某个包没有预编译版本，需要在本地编译 C++ 扩展。
**解决（按推荐顺序）**：
1. **先找有没有预编译包**：换 Python 版本（推荐 3.12）、或升级 pip：
   ```powershell
   python -m pip install --upgrade pip
   ```
2. 装编译器（体积约 6GB，装一次管很久）：
   下载 <https://visualstudio.microsoft.com/visual-cpp-build-tools/>，
   安装时勾选 **「使用 C++ 的桌面开发」**。
3. 或者用 conda 装（conda 有更多预编译包）：
   ```powershell
   conda install -c conda-forge 包名
   ```

---

### E05
```
error: externally-managed-environment
```
**原因**：你在用一个「系统级」Python（常见于 Linux / WSL 的 Ubuntu）直接装包，被保护机制拦截。
**解决**：用虚拟环境，这是唯一正确的做法。
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install xxx
```
实在急用（不推荐）：
```bash
pip install xxx --break-system-packages
```

---

### E06
```
ERROR: Could not find a version that satisfies the requirement xxx
ERROR: No matching distribution found for xxx
```
**原因**：① 包名拼错；② **这个包没有你当前 Python 版本的预编译包**（最常见的真凶）；
③ 网络问题（连不上 PyPI，被误报成「找不到」）。
**解决（按这个顺序排查）**：
```powershell
# ① 看看报错详细原因
python -m pip install 包名 -v

# ② 去 PyPI 看这个包有没有你版本的 wheel
#    浏览器打开 https://pypi.org/project/包名/#files
#    找形如 xxx-cp312-cp312-win_amd64.whl 的文件
#    cp312 = Python 3.12，win_amd64 = 64 位 Windows
#    如果只有 cp310/cp311，说明你的 Python 太新了

# ③ 只想用预编译包，装不了就明确报错（而不是偷偷去编译）
python -m pip install 包名 --only-binary :all:

# ④ 判断是不是网络问题：换国内源，能装就说明是网络
python -m pip install 包名 -i https://pypi.tuna.tsinghua.edu.cn/simple
```
> ★ **遇到这个问题，第一个该怀疑的是「我的 Python 版本太新了」。**
> 换回 Python 3.12 通常立刻解决。这是新手最容易忽略的原因。

### E07
```
SSLError: HTTPSConnectionPool ... SSLCertVerificationError
CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate
```
**原因**：① 公司/学校网络有中间人代理（最常见）；② 系统时间不对；③ 证书链缺失。
**解决（按这个顺序，不要一上来就关校验）**：
```powershell
# ① 先检查系统时间是否正确 —— 时区/时间错了证书必然校验失败

# ② 更新证书库
python -m pip install --upgrade certifi

# ③ ★ 最有效的办法：让 pip 信任 Windows 系统证书库
python -m pip install pip-system-certs

# ④ 如果学校给了 CA 证书，显式指定
python -m pip install 包名 --cert C:\path\to\ca.pem
# 或者设环境变量
$env:PIP_CERT = "C:\path\to\ca.pem"

# ⑤ Git 遇到同样问题时（让它用 Windows 证书库而不是自带 OpenSSL）
git config --global http.sslBackend schannel
```
> ⚠️ **不推荐的写法**：`--trusted-host pypi.org`。
> 它的意思是「不要校验证书」，等于关掉了 HTTPS 的安全保护。
> 只在完全可信的内网里临时用，**不要写进永久配置**。

### E15
```

```
**原因**：① **你在往系统级 Python 目录里装包**（最常见）；

### E17
```

CUDA out of memory
torch.cuda.OutOfMemoryError: Tried to allocate ...
```

**原因**：显存或磁盘不够（训练 RL 时最常见）。
**解决**：

训练时的显存优化（按有效性排序）：
1. **减小 batch size** —— 最有效，先试这个
2. 减小模型规模 / 序列长度
3. 混合精度训练（AMP）
4. 梯度累积：小 batch 多次累积，模拟大 batch
5. 梯度检查点（gradient checkpointing）

```powershell

```

### E22

**原因**：远程有你本地没有的提交（比如队友刚推了代码）。
**解决**：

### E23
合并冲突（merge conflict）
```
CONFLICT (content): Merge conflict in code/agent/agent.py
Automatic merge failed; fix conflicts and then commit the result.
```
**原因**：你和队友改了同一个文件的同一部分。
**解决**：
1. 打开冲突文件，会看到：
   ```
   <<<<<<< HEAD
   你写的代码
   =======
   队友写的代码
   >>>>>>> origin/main
   ```
2. **手动决定**保留哪些行，然后删掉 `<<<<<<<`、`=======`、`>>>>>>>` 这三行标记。
3. 然后：
   ```powershell
   git add 冲突的文件
   git commit -m "merge: 解决 agent.py 冲突"
   ```
**预防**：**开工前先 `git pull`，收工就 `git push`。** 不要攒一周再提交 ——
那样冲突会变成噩梦。
**VS Code 有图形化冲突解决界面**，比手改安全得多，推荐用。

```
（.ps1 脚本报一堆「看不懂」的语法错误，但你检查代码明明是对的）
```
**原因**：PowerShell 脚本的**文件编码问题**，不是代码问题。

Windows PowerShell 5.1（就是系统自带那个）在文件**没有 BOM** 时，
会按系统 ANSI 代码页（中文 Windows 是 GBK/cp936）去解码 `.ps1`。
于是脚本里的中文全变成乱码，**乱码字节会破坏字符串引号的配对**，
最终报出与真实原因完全无关的语法错误。

**关键识别特征**：报错行号指的地方看起来完全正常，而且报错数量很多、互相矛盾。

**解决**：把文件重新保存为 **UTF-8 with BOM**。

```powershell
# 修复（在 PowerShell 里执行）
$p = 'scripts\push-to-github.ps1'
$t = Get-Content $p -Raw -Encoding UTF8
[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($true)))

# 验证：应输出 239,187,191
([IO.File]::ReadAllBytes($p)[0..2]) -join ','
```

**用 VS Code 的话**：右下角点编码 → `Save with Encoding` → 选 **UTF-8 with BOM**。

⚠️ **注意区分**：很多编辑器「另存为 UTF-8」会**默认去掉 BOM**，
所以改完 `.ps1` 一定要验证一次。

> 💡 **一句话记忆**：
> - **Python / Markdown / HTML** → UTF-8 **不带** BOM（带 BOM 反而会让 Python 报错）
> - **Windows PowerShell 脚本（.ps1）** → UTF-8 **带** BOM
> - **.bat 批处理** → 干脆别写中文（见下面 E28）
>
> 本仓库的 `scripts/setup_check.py` 会自动检查这个，直接跑它就能发现问题。

### E28
```
'xxx' is not recognized as an internal or external command,
operable program or batch file.
（.bat 文件里的中文被当成命令执行了）
```
**原因**：`cmd.exe` 解析 `.bat` 文件时用的是 **OEM 代码页**（中文 Windows 是 cp936），
而不是 UTF-8。文件里的中文（UTF-8 字节）被按 cp936 解码成乱码，
**乱码里恰好出现的空格和符号会把一行拆成多条「命令」**，于是报错。

**加 `chcp 65001` 也救不了** —— 因为 cmd 在**读取脚本字节流的时候**
就已经按当前代码页解码完了，`chcp` 是在那之后才执行的。

**解决**：**`.bat` 文件里不要写中文**，全用 ASCII 英文。
中文输出交给它启动的 Python 程序（Python 自己会正确处理 UTF-8）。

如果非要写中文，只能把文件另存为 **ANSI/GBK** 编码 ——
但这会让非中文系统的队友那边乱码，所以**不推荐**。

> 💡 本仓库的 `run_demo.bat` 就是**全英文**的，原因写在文件头注释里。
> 别"好心"把它翻译成中文 —— 会直接坏掉。
